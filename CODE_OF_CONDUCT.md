# Code of Conduct

## Scope

This code applies to participation in this project's issues, pull requests, reviews, discussions, and other project-managed spaces. It also applies when someone represents the project publicly.

## Expected behavior

Treat contributors and users with respect, regardless of experience, identity, background, or viewpoint. Give constructive feedback, focus criticism on the work, accept corrections, and respect other people's time and privacy. Disagreement is welcome when it remains professional and relevant to the project.

## Unacceptable behavior

Harassment, discrimination, threats, personal attacks, sexual harassment, and deliberate disruption are unacceptable. Do not publish another person's private information without permission. Do not post passwords, access tokens, private device configurations, or sensitive network details.

## Reporting concerns

For concerns that can safely be discussed publicly, open a GitHub issue describing the conduct and its impact without exposing private information. For sensitive concerns, request a private reporting channel from the repository owner without posting identifying details or evidence publicly. The project currently does not publish a dedicated confidential contact address; GitHub issues are public and should not be treated as a private reporting channel.

Security vulnerabilities should follow the process in [SECURITY.md](SECURITY.md).

## Enforcement

The repository owner and designated maintainers may moderate project spaces and remove, edit, or reject content that violates this code. Depending on severity, repetition, and context, they may issue a warning, restrict participation temporarily, or block further participation. Serious threats, harassment, or disclosure of private information may lead to immediate restrictions.

Maintainers should explain moderation decisions where appropriate, protect sensitive information, and apply these expectations consistently, including to themselves. A person affected by a moderation decision may request reconsideration by providing relevant context through an available safe contact channel. No response time is guaranteed.

## Language

English and Polish are welcome in project communication. Language mistakes and differences in technical experience are not grounds for ridicule or exclusion.
